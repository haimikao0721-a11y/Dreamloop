# 角色设计规范

> 一个角色的"身份"现在分居两处：`packs/core/roles.ts` 里的六个数字（回合制资产，仍在跑），
> 和 `data/rt/actions.ts` 里的帧数据（实时层，四步迁移已做完，但仍是一条并行的路）。
> 只写一处就发布，玩家看到的会是一个半成品。

这份文档写给**要加角色、要调角色数值**的人。读完你应该能回答三个问题：
字段填什么、帧数怎么定、加完一个角色要动哪些文件。

---

## 一、先分清两层（不读这段一定写错文件）

```
src/data/packs/core/roles.ts ──→ src/core/engine.ts ──→ 正式游戏（main.ts，回合制）
src/data/rt/actions.ts       ──→ src/core/rt/loop.ts  ──→ ?proto=rt（实时层）
```

实时层是一条**并行**的路：四步迁移已经做完（移动 / 帧数据战斗 / 理智与光 / 接回叙事层），
但默认入口走的仍然是回合制那一条。这一点 `06-实时架构.md` 第一节的「实现差异」写得很清楚。

两套数值体系**不共用一张表**，这是刻意的（见 `data/rt/actions.ts` 顶部注释）。
代价是：同一个角色有两份互相不知道对方存在的身份。

### `RoleDef` 的字段在实时层到底生效几个

| 字段 | 回合制怎么用 | 实时层现状 |
|---|---|---|
| `hp` | `engine.ts` 设 `hp` / `hpMax` | **不读角色**。`createInitialRtState` 出生固定 22，`rt-view.ts` 再写一次 22 |
| `san` | `sanMax = role.san`（30 / 18） | **不读**。`sanMax = SANITY_MAX = 100` |
| `atk` | `combat.rollDamage` = `max(1, atk - def + rng.int(-1,1))` | **参与伤害，但语义变了**：实时层伤害 = `max(1, ActionDef.damage + 玩家 atk − 目标 def)`，`atk` 是**加成**（基础 0）。角色那 5 点从来没被传进来 |
| `def` | 同上（减法公式的减数） | **参与伤害，语义也变了**：只在"玩家挨打"时作为**减伤**（基础 0）。角色那 1 点从来没被传进来 |
| `tags` | 剧情 `requiresTag` 门控 | 走 `RtState.roleTags`，原型里默认 `[]` |
| `startItems` | `engine.ts` 发进 `inventory` | **不发**，且实时层没有"使用道具"的入口 |

> **结论**：实时层里两个角色的差异，现在**全部**由 `actions.ts` 的帧数据承担。
> 改 `roles.ts` 的 hp / atk / def 不会改变实时层的手感 —— 想让实时层的角色不一样，只能改帧数据。
> 注意"实时层没有攻防"这句话已经不成立了：实时层有 `atk`（加成）和 `def`（减伤），机制是通的，
> 只是**没有任何地方把角色的数值接进去**（叙事层的 `buff` 才是目前唯一写它们的入口）。

素材上也是这个格局：`assets/characters/<roleId>/actions/` 每个角色三张图（`idle` / `move` / `attack`），
`attack.png` 三帧横排，直接对应起手 / 判定 / 收招三段（见 `assets/README.md`）。

## 二、`RoleDef` 字段含义

| 字段 | 类型 | 写什么 | 谁读它 | 不要写什么 |
|---|---|---|---|---|
| `id` | string | 小写蛇形，全局唯一 | 存档、素材目录名、`startRun` | 中文、空格、大写 |
| `name` | string | 中文显示名 | 选人界面、日志 | 称号（那是 badge 的事） |
| `desc` | string | 1~2 句，用 `\n` 分段，要让人产生选择欲望 | 选人界面 | 数值说明、玩法教学 |
| `hp` | number | 初始生命 = 上限 | 回合制 | 当作实时层血量用 |
| `san` | number | 初始理智 = 上限 | 回合制 | 当作实时层理智上限用（那边是 100） |
| `atk` | number | 攻击 | 回合制减法公式 | 以为它影响帧数据伤害 |
| `def` | number | 防御 | 回合制减法公式 | 堆太高：减法公式里 `def` 比 `atk` 值钱得多 |
| `tags` | string[] | 剧情门控键，**不与已占用的重合** | `StoryChoice.requiresTag` | 已存在的 tag（会削弱分叉） |
| `startItems` | string[] | `items.ts` 里真实存在的 id | `engine.ts` | 不存在的 id（有测试守着） |

### tag 的现实情况（2026-10-15 读代码所得）

| tag | 属于 | 有内容读它吗 |
|---|---|---|
| `scholar` | 记梦者 | **有**，`stories.ts` 里 9 处 `requiresTag` |
| `healer` | 值夜护士 | **有**，6 处 |
| `lucid` / `frail` | 记梦者 | **没有**，只有注释提到 |
| `believer` / `steadfast` | 值夜护士 | **没有** |

`roles.ts` 顶部写"剧情门控就靠这六个 tag 分叉"，实际是**靠两个**分叉，另外四个是预留位。
加新角色时不必躲开这四个没人读的 tag，但**必须**躲开 `scholar` 和 `healer`。

### 数值的两条硬约束

1. **tag 集合不重合**（`02-数据字典.md` 第二节）——否则角色分叉会被削弱。
2. **理智高的角色战斗属性低，反之亦然**——`roles.ts` 把这条写成"本作唯一的核心资源"的体现。

减法公式 `max(1, atk - def + rng.int(-1, 1))` 有一个已知陷阱，写在 `roles.ts` 和 `03-第一幕设计.md` 第六节里：
`atk ≈ def` 时伤害会塌陷到 1，而且**只坑低攻击力角色**。逻辑推演在那里，这里不重复。

## 三、帧数据怎么填

单位全是 tick，`60 tick = 1 秒`（`core/rt/loop.ts` 的 `TICK_RATE`）。

### 3.1 三段的真实语义

判定只看 `core/rt/action.ts` 的 `actionPhase` / `collectHits`：

| 阶段 | 代码判定（`as.frame`） | 能打到人吗 | 这段时间里玩家在做什么 |
|---|---|---|---|
| 起手 startup | `frame < startup` | 不能 | 对手**能看见并走开**——这就是起手帧存在的理由 |
| 判定 active | `startup ≤ frame < startup + active` | **只有这一段** | 命中在判定帧里结算，`hasHit` 保证一招对同一目标只算一次 |
| 收招 recovery | `< startup + active + recovery` | 不能 | 能动之前**必须站完**——这就是打空的代价 |
| idle | `def === null` | 不能 | 唯一能出下一招、能移动的状态 |

三条实现细节，填数值时必须知道：

1. **判定帧加长不等于伤害变高**。`hasHit` 按实体 id 记账（`applyHits`），一招对同一个目标只结算一次。
   3 帧判定和 6 帧判定的区别是**容错**（对手在判定期间走进范围也算命中），不是伤害。
2. **出招全程定身**。`loop.ts` 对被 `canAct` 拒绝的实体清零速度，玩家也一样 ——
   `startup + active + recovery` 不是"动画时长"，是**你把自己钉在原地的时长**。
3. **冲刺位移只在起手帧生效**（`actionDash`）。判定帧还能滑的话，对手躲开了起手也会被追上，起手帧就白设计了。
   目前六个动作的 `moveX` / `moveY` 都是 0，即没有冲刺攻击。
4. **一个实体身上可以挂两招**：`Entity.attack`（轻击）和 `Entity.heavyAttack`（重击），
   分别由 `InputState.attack` / `InputState.heavy` 触发，两个都是边沿触发。
   **同一 tick 两个都按 → 轻击生效**：`loop.ts` 先 `beginAction(attack)` 再判 `heavy`，
   而出招中的实体再调 `beginAction` 会返回 false。那里的注释写着"重击优先"，**和代码相反**，以代码为准。

### 3.2 各字段的责任

| 字段 | 单位 | 你填它的时候在决定什么 | 常见错法 |
|---|---|---|---|
| `startup` | tick | 对手有多少时间离开你的判定范围 | 填太小 → 只能拼反应，读不出来；填太大 → 只能用来打不会动的目标 |
| `active` | tick | 容错窗口（对手移动 / 你朝向没对准） | 以为加长能加伤害；以为这是"手感"，其实是判定宽容度 |
| `recovery` | tick | 打空之后你要赔多少时间 | 轻重击的收招拉不开差距 → 重击变成废字段 |
| `range` | 像素 | 攻击距离 | 忘了实际距离是 `range + max(目标 hw, 目标 hh)`，比直觉远 |
| `arc` | 度 | 身前的扇形 | 用 360 会变成"原地转圈"，看不出打向哪。`swing()` 工厂统一 90 |
| `damage` | 点 | 这一招的**基础**伤害。实际伤害 = `max(1, damage + 玩家 atk − 目标 def)`（原型里两者都是 0，所以就是它本身） | 把它当成最终伤害去算，忘了叙事 buff 会在上面加减 |
| `knockback` | 像素 | 把目标推开多远。**一次性瞬时位移，走碰撞** —— 撞墙就停住，不会被推进墙里 | 当成速度冲量：它是瞬移一段距离，不是"推飞"，也不产生硬直 |
| `moveX` / `moveY` | 像素 | 冲刺攻击的位移，只在起手帧生效 | 判定帧还带位移 |

### 3.3 tick 换算表（推导值，不是代码里的常量）

玩家 `speed = 90` 像素/秒 = **1.5 像素/tick**；爬行物 62 = 1.03；护工 34 = 0.57。
（所有速度单位都是像素/秒，见 `Entity.speed`。）

| tick | 秒 | 玩家能走 | 爬行物能走 | 护工能走 |
|---|---|---|---|---|
| 6 | 0.10 | 9.0 px | 6.2 px | 3.4 px |
| 8 | 0.13 | 12.0 px | 8.3 px | 4.5 px |
| 10 | 0.17 | 15.0 px | 10.3 px | 5.7 px |
| 14 | 0.23 | 21.0 px | 14.5 px | 7.9 px |
| 18 | 0.30 | 27.0 px | 18.6 px | 10.2 px |
| 26 | 0.43 | 39.0 px | 26.9 px | 14.7 px |
| 39 | 0.65 | 58.5 px | 40.3 px | 22.1 px |
| 48 | 0.80 | 72.0 px | 49.6 px | 27.2 px |

**这张表是调帧数的主要工具**：填入 `startup: 14` 之前先问"对手在这 14 tick 里能走多远，够不够离开我的 range"。

> 一个反直觉的结论：**玩家的速度是全局常量，不是角色属性**。
> `RoleDef` 里没有 `speed` 字段，"护士比记梦者慢"这种设定在当前代码里**无法表达**。
> 要做角色化的移动速度，得先给角色加字段、再让生成玩家的地方读它。

### 3.4 正确的填写顺序

1. 先写一句话：**玩家用这一招要做什么决策**（例：贴上去换一次赚、或者打一下就撤）。
2. 定这个决策需要多宽的窗口，反推 `startup`（能不能躲）和 `recovery`（打空赔多少）。
3. 定 `range` / `arc`（打不打得到，往哪打）。
4. **最后**才填 `damage` 和 `knockback`。

> 反着来的话一定得到"重击全面优于轻击"或者反过来 —— 因为你是拿伤害去凑帧数的。

## 四、加一个新角色要做什么

| 步 | 文件 | 做什么 | 不做的后果 |
|---|---|---|---|
| 1 | `src/data/packs/core/roles.ts` | 加一个 `RoleDef`，tag 避开 `scholar` / `healer` | 选人界面看不见；或剧情分叉被削弱 |
| 2 | `src/data/rt/actions.ts` | 加轻 / 重两招，用 `swing()` 工厂 | 实时层里这个角色没有战斗身份 |
| 3 | `src/data/packs/core/items.ts` | 起始物品必须真实存在 | `content.test.ts` 直接红 |
| 4 | `assets/characters/<roleId>/actions/` | `idle.png`(1 帧) / `move.png`(2 帧) / `attack.png`(3 帧) | 画面退回色块（不会崩，见 `rt-view.ts` 的 `loadImage` 兜底） |
| 5 | `src/data/packs/core/stories.ts` | 想让它看到专属选项，就加带 `requiresTag` 的选项 | 只有数值差异，没有叙事差异 |
| 6 | 测试 | 跑 `pnpm test`，看 4 条平衡守卫 | 见下 |

### 平衡守卫（全部在 `tests/content.test.ts`，且**只测回合制**）

| 守卫 | 阈值 |
|---|---|
| 能跑完本幕的种子比例 | ≥ 0.8 |
| 中位死亡次数 | ≤ 5 |
| 两个角色的难度比 `(frail+1)/(sturdy+1)` | ≤ 4 |
| 清房间打法活着走完第一层 | ≥ 0.5（4 个种子里） |

> 这四条守的是"回合制那边角色还能不能玩"。**实时层没有任何平衡守卫**，
> `actions.ts` 的帧数目前只被`tests/rt-combat.test.ts`测过边界（起手打不到、判定够 3 帧、收招不能出招），
> 没有任何一条测试关心"这套帧数玩起来是什么感觉"。

### 现在还做不到的事（加角色前必须知道）

> `docs/06-实时架构.md` 第六节末尾有一张「实现差异」表（第十五节之后还有一张缺口表）。
> 截至 2026-10-15 21:30 那次提交，它们仍写着"击退是死字段""没有任何输入能打出重击""`atk`/`def` 根本不参与"，
> 而**代码已经把这三条都改掉了**：击退接进 `loop.ts` 的命中步骤、重击接进 `InputState.heavy` /
> `Entity.heavyAttack` / K 键与手机按钮、攻防接进伤害公式（见 3.2）。
> 两处说法冲突时**以代码为准** —— 引用 06 的时候请连同这几条一起核一遍。

| 想做的 | 卡在哪 |
|---|---|
| 一个角色有轻击 + 重击两招 | **通路已经有了**：`InputState.heavy`（边沿触发）、`Entity.heavyAttack`、原型上的第二个按钮。卡住的是角色侧 —— 只有记梦者的两招被接上（`NURSE_LIGHT` / `NURSE_HEAVY` 还挂在数据里没人用） |
| 实时层按角色切换数值 | `?proto=rt` 原型把玩家写死（`player.attack = ARCHIVIST_LIGHT` + `heavyAttack = ARCHIVIST_HEAVY`、`hp = 22`、素材 `dream_archivist`），不传 `roleId` / `roleTags` |
| 实时层使用起始物品 | 实时层没有 `useItem` 路径（只有回合制 `engine.ts` 有）；`inventory` 只被写入，没有代码读它 |
| 角色化的移动速度 | `RoleDef` 和 `Entity` 生成处都没有按角色取速度的地方，玩家速度是字面量 90 |
| 击退做成速度冲量 | 现在是**一次性瞬时位移**（`loop.ts` 直接 `moveAndCollide` 推一段），大位移已拆成半格一步防穿墙 —— 但没有"被推飞"的滑行感，也不产生硬直 |

## 六、这份文档是怎么来的

数字全部来自 2026-10-15 读取的代码：`packs/core/roles.ts`、`data/rt/actions.ts`、
`packs/core/items.ts`、`packs/core/enemies.ts`、`data/rt/enemies.ts`、`core/rt/action.ts`、
`core/rt/loop.ts`、`core/rt/ai.ts`、`core/rt/sanity.ts`、`core/rt/light.ts`。

标注为**推导**的数字（秒伤、击杀所需时间、位移换算）是拿代码里的常量算出来的，**不是代码里写着的结论**。
`src/ui-web/rt-view.ts` 在写这份文档时正被改动（`?proto=rt` 原型在做迁移计划第 4 步），
引用它的地方都只写"当前状态"，不写行号。
`docs/06-实时架构.md` 同期也在被更新（逐节加「实现差异」标注），本文档引用它时按**标注后**的版本描述，
不再把它已经自己纠正过的地方算成"文档和代码对不上"。
`src/core/rt/` 在同一个晚上还改了四件事，本文档按**最后一次核对时的代码**写：
攻防进伤害公式、击退接上（两者见 3.2）、重击的输入通路（`InputState.heavy` / `Entity.heavyAttack`）、
玩家死亡判定接回结局（`endRun` + `died` 事件）。
**读这份文档时如果代码已经又变了，以代码为准** —— 每张表都标了来源文件。
