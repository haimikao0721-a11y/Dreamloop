# 05 · 表现与文字

> 字是数据，画面是文件，播放是界面，停住操作是规则。

这一篇只定分层。不改 `phase`，不改 `StoryNode`，也不做播放器。
素材放在哪见 [assets/README.md](../assets/README.md)。

---

## 一、现在已经有的路

全屏叙事是一条完整的路：

- 内容包里的 `StoryNode.text`、`quote`、选项是要说的字
- core 用 `phase: 'story'` 停住操作
- UI 收到 `story` 事件后排版

死亡和结局走 `dead` / `actEnd`。界面按钮和提示在 `src/ui-web/render.ts` 的 `UI_TEXT`。

过场动画沿这条路长出来，不另起一套引擎。

```
data     这一拍说什么、用哪张画面的 id
core     现在能不能操作
ui-web   淡入、打字、缺图时退回纯文字
assets   画面文件
```

四面都只交给 UI。data、core、素材文件之间不互相指向路径。

---

## 二、四件事各管一块

**字是数据。** 剧情正文、引用、选项、结局、角色介绍继续留在 `src/data`。过场某一拍上的字幕也是数据，跟正文同一类，不刻进图片。改一句不用重导素材。

**画面是文件。** 过场画面只放在 `assets/cutscenes/<cutsceneId>/`。内容里只写画面 id，不写路径。角色动作、地形、物品各自有目录，不复制进过场目录。

**播放是界面。** 淡入、打字速度、播多久，都在 `ui-web`。缺了图就显示这一拍的字，游戏照样能玩。core 里不出现时长、CSS、文件名。

**停住操作是规则。** 需要玩家读完才能走的段落，继续用现有的 `story` / `dead` / `actEnd`。core 不知道播到第几帧。

界面上的「下楼」「离开」「你死了」留在 `UI_TEXT`。那是壳，不是世界观，不放进内容包，也不放进过场目录。

---

## 三、两种过场

不要合成一种。

### 系统过场

不进内容包。换层（`floorChanged`）、打开和关上剧情（`story` / `storyClosed`）、死亡、结局，UI 自己在现有事件上播一段过渡。

用的字就是现在已有的：`UI_TEXT.floorReached`、剧情正文、结局文。不新增 `phase`。过渡播不播完都不改 `GameState`，避免动画时长拖进种子复现和测试。

### 内容过场

作者写的一串拍，将来挂在剧情节点前面。每一拍只有可选的画面 id 和可选的一句字。播完最后一拍，才显示现在的正文和选项。

选项仍由 core 的 `getVisibleChoices` 决定。过场不自己长出分支。

这一轮不给 `StoryNode` 加字段。上面是以后接入时要守的形状。
