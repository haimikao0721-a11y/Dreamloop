# 03 · 第一幕设计与平衡记录

> 这份文档有两个目的：
> 1. 让加第二幕的人知道第一幕**长什么样**（结构、flag 图、结局路径）

## 二、叙事槽位与剧情节点的对应

每一层生成时会预留四种槽位。剧情节点通过 `slots` 声明自己适合出现在哪。

| 槽位 | 数量 | 含义 |
|---|---|---|
| `ENTRY` | 每层必 1 | 入口房，放引入 |
| `MID` | 每层 1~2 | 中层房，放支线 / lore |
| `PREBOSS` | 每层必 1 | 楼梯房，放高潮 / 重大抉择 |
| `SECRET` | 30% 概率 | 最偏远的房间，放隐藏内容 |

### 节点分布

| 节点 | 槽位 | 出现条件 | 正文 |
|---|---|---|---|
| `story_entry_wake` | `ENTRY` | 无（刻意不设 maxDepth，保证任何层的入口都填得满） | 90 字 |
| `story_missing_minute` | `ENTRY` | `saw_clock=true` 且 层 ≥ 2 | 80 字 |
| `story_repeat_room` | `MID` | `deaths >= 1` ← **首周目看不见，这是刻意的** | 86 字 |
| `story_chart_name` | `MID` | 持有 `torn_case_notes` 且 层 ≥ 2 | 89 字 |
| `story_third_bell` | `PREBOSS` | 层 ≥ 2 | 83 字 |
| `story_handover` | `PREBOSS` | 层 ≥ 3 | 81 字 |
| `story_case_page` | 不限 | 无 | 78 字 |
| `story_mirror_face` | 不限 | 无 | 82 字 |
| `story_cylinder_playback` | 不限 | 无 | 98 字 |
| `story_the_other_bed` | `SECRET` | 无 | 74 字 |

> ⚠️ **后三个节点刻意不写 `requires` / `slots`** —— 它们是**叙事物件触发的**。
> 物品触发时不该再检查出现条件，否则会出现「东西拿到了，剧情却不弹」这种最让人困惑的 bug。
> 这条有测试强制守着。

### 三个叙事物件 ↔ 节点

| 物品 | → 剧情节点 |
|---|---|
| `torn_case_notes` 撕裂的病历 · 第三页 | `story_case_page` |
| `cracked_mirror_shard` 裂镜残片 | `story_mirror_face` |
| `wax_cylinder` 蜡筒 | `story_cylinder_playback` |

## 三、角色门控：同一段剧情，两种视角

两个角色的 tag **完全不重叠**：

```
记梦者   scholar / lucid  / frail
值夜护士 healer  / believer / steadfast
```

10 个节点里有 **7 个** 带 `requiresTag` 的选项。这是"角色选择改变剧情"的全部机制 ——
加新角色只需要给它一组没被占用的 tag，**不用改任何剧情数据**。

### 每个节点的角色差异

| 节点 | 学者的选项 | 医者的选项 |
|---|---|---|
| `story_entry_wake` | 把门口的值班牌读一遍（−3 理智） | 先数一数还躺着几个人（**+2 理智**） |
| `story_missing_minute` | 在值班记录上把那一分钟补上（**写 `knows_the_name`**） | — |
| `story_repeat_room` | 在墙上记下这一次（`loop_marks+1`，−6） | 给三号床的人盖好被子（**+4 理智**） |
| `story_chart_name` | 把卡片夹进病历带走（**给 `sleepers_ledger`**，→ 跳转） | 把床栏拉起来扣好（+4 理智，**回血 +3**） |
| `story_third_bell` | 在记录上写"三点十七分，铃响三次"（−5） | — |
| `story_handover` | 拉开桌子下面的抽屉（**给 `hollow_tonic`**） | 先把三号床的记录补齐（**写 `signed_the_handover`**，回血 +6） |
| `story_case_page` | 比对一下笔迹（**写 `knows_the_name`**，−7） | — |
| `story_mirror_face` | — | 照一照自己的手（**+5 理智**，回血 +2） |
| `story_cylinder_playback` | 在设备清单上找这台机器的编号（−3） | — |
| `story_the_other_bed` | 看床尾的牌子（−3） | 替他把被子掖好（+3 理智） |

**设计规律**：
- **学者**走"知道真相"路线 —— 大量选项写 `knows_the_name`，代价是理智
- **医者**走"照顾他人"路线 —— 大量选项回理智、回血，但很少写 `knows_the_name`

两条路**通向不同的结局**。这是第一幕最重要的分叉。

## 四、flag 依赖图

结局判定**不是一棵选择树，是一个条件集合**。所有 flag 都来自选项或物品。

### 三个结局真正依赖的 flag（只有 5 个）

| flag | 谁写的 |
|---|---|
| `knows_the_name` | `story_missing_minute` / `story_chart_name` / `story_handover` / `story_case_page` / `story_cylinder_playback` —— **5 个节点都能写，学者路线更容易拿到** |
| `signed_the_handover` | `story_handover`（医者选项也置位） |
| `carries_the_coin` | **物品 `returning_coin`（遗物，获得时结算）** |
| `moved_the_hand` | `story_third_bell` |
| `traded_flesh` | **物品 `hollow_tonic`（使用时结算）** |
| `has_died` | 引擎（死亡时自动写） |

> ⚠️ **两个 flag 由物品写，不由剧情写**：`carries_the_coin` 和 `traded_flesh`。
> 这是引擎里一个曾经的 bug：遗物的 `effects` 被当成纯被动数据从不结算，
> 导致「接班的人是你」这条结局**永远不可达**。现在拾取遗物时立刻结算，有测试守着。

其余 20 多个 flag（`saw_clock`、`checked_pockets`、`kept_the_card`…）
是**叙事质感**，不参与结局判定 —— 它们让世界对玩家的选择有记忆，
但不构成"必须凑齐"的压力。

## 五、三个结局与达成路径

### `ending_signed_the_shift`「接班的人是你」 priority 30

```
knows_the_name  AND  signed_the_handover  AND  carries_the_coin
```

**怎么走到**：
1. 在 `story_third_bell` 之前拿到 `knows_the_name`（5 个节点任选其一，学者更容易）
2. 到第三层的 `story_handover`，在接班人那一栏签名（或医者选项"补齐记录"）
3. 路上捡到遗物 `returning_coin`（`cracked_watch` 那类掉落）

> 提示文案：*在还记得那个名字的时候，把手续签下去 —— 并且别把那枚硬币落下。*

### `ending_seventeenth_minute`「第十七分钟」 priority 20

```
moved_the_hand  AND  (traded_flesh  OR  deaths >= 1)
```

**怎么走到**：
1. `story_third_bell`（第二层起的 `PREBOSS` 槽）选"伸手把指针拨过去"，−8 理智
2. 然后**要么**用过 `hollow_tonic`（拿理智换命），**要么**死过至少一次

> 这条结局的 `any` 分支是**给死亡兜底的** —— 保证"变强要付代价"这件事
> 哪怕玩家没找到那瓶药，也有一条成立的路径。

### `ending_nobody_came`「没有人来接班」 priority 0

`requires: []` —— **兜底结局**。

内容包必须提供它，否则玩家会走到"没有结局"。
`judgeEnding` 里还有一层最后防线：万一社区包忘了写兜底，引擎会现造一个。

## 六、平衡调整记录（全部有实测依据）

这一节是**这份文档最重要的部分**。第一幕的数值不是拍脑袋定的，
是四轮"测量 → 定位 → 修改 → 再测量"的产物。**把它写下来，是为了下一个人不重踩。**

### 6.1 测量工具

自动化测试里有一个机器人，可以按三种打法游玩：

| 打法 | 策略 | 测的是 |
|---|---|---|
| `rush` | 见到楼梯就走，BFS 最短路径 | 单局**下限** |
| `normal` | 清到七成房间就走 | **最接近真人** |
| `thorough` | 一个房间不落 | 单局**上限** |

**关键指标**：`medians` 用**中位数**不用平均；难度用**首次死亡深度**（不复合）
而不是总死亡数（会通过"重开→再清→再死"复合放大，掩盖真问题）。

### 6.2 第 1 轮：记梦者是个废角色

**症状**：中位死亡 **17 次**，最多 60 次。值夜护士只有 2 次 —— **6 倍差距**。

**根因**：减法伤害公式在 `atk ≈ def` 时会塌陷。

```
记梦者 atk3 打 def2 的怪 → 伤害 1/下 → 打 20hp 的怪要 20 回合
而怪打他 5~6 一下 → 必死
```

这个陷阱**只坑低攻击力角色**：

```
护士 atk6 打 def0~2  →  6~4 伤害，只差 1.5 倍
记梦者 atk3 打 def0~2 →  3~1 伤害，差 3 倍
```

**改动**：记梦者 `hp 16→22`、`atk 3→5`；第三层两只怪 `def 2→1`。
**没有**动 tags 和 san —— "frail"和"理智高"的身份保留。

**结果**：中位死亡 17 → 3，难度比 6 倍 → 1.3 倍。

### 6.3 第 2 轮：发现前面的守卫测错了对象

`rush` 打法的平衡守卫通过了，但那是**因为速通根本不怎么打架**。

换成 `normal` 打法后：记梦者死 **108~119 次**，永远卡在第一层。

**这是「清房间掉叙事物件」这条核心内容链路被战斗挡住了** ——
玩家还没看到剧情就先死了。

### 6.4 第 3 轮：定位到系统性问题

逐条命诊断：

```
第1条命: 活了116步, 最深第3层     ← 这条才是异常值
第2条命: 活了 25步, 最深第1层
第3条命: 活了 24步, 最深第1层
```

不是"重开有惩罚"，是**每条命只能打 2~5 架**。而：

| | 每架掉血 | 一条命能打几架 | 一层有几架 |
|---|---|---|---|
| 记梦者 hp22 / def1 | 4 ~ 9 | **2 ~ 5** | 4 ~ 7 |
| 值夜护士 hp26 / def2 | 2 ~ 6 | 4 ~ 13 | 4 ~ 7 |

**两个角色都清不完一层，护士只是勉强。**

深层原因：**这个游戏的战斗经济里没有可再生的治疗。**
全局唯一像样的治疗品是 `hollow_tonic`（heal +14 / san −7），而且是随机掉落。

还有一条容易忽略的：**`def` 在减法公式里太值钱**。
记梦者 def1 对 atk4 挨 3 血，护士 def2 只挨 2 血 —— **差 33%**。
而"低防御"正是 frail 的身份，动不得。

### 6.5 第 4 轮：系统性修复

| 改动 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `enemiesPerFloor` | `[4, 7]` | `[3, 5]` | 剧情向游戏，战斗不该占满整层 |
| 全体怪物 `atk` | 3~7 | **2~6** | 减法公式下 −1 攻击是很大的一步 |
| 记梦者 `startItems` | `sedative_ampoule` | **`hollow_tonic`** | 见下 |

**起始物品那一处的理由值得单独说**：

原来给它的是回理智的镇静剂，而记梦者理智本来就最多（30）——
**优势花不出去**，而且 heal 只有 2，战斗里等于没有。

换成 `hollow_tonic`（heal +14 / san −7 / 置 `traded_flesh`）之后：

- 玩家**第一次亲手体会核心张力** —— 拿理智买命
- 顺带把记梦者推向「第十七分钟」那条结局（用理智换力量的人，时间会把他收回去）
- 不需要新增任何内容

### 6.6 最终结果

| 指标 | 修复前 | 现在 |
|---|---|---|
| 记梦者中位死亡（速通） | 17 次 | **0 次** |
| 探索打法能否跑完本幕 | 卡在第一层死循环 | **能跑完** |
| 探索打法首次死亡 | 第 1~3 层 | 第 2~3 层 / 没死 |
| **测试套件耗时** | **51 秒** | **15.6 秒** |

最后一行是最好的证据：**套件快了三倍，因为机器人不再跑 6000 步死亡循环了。**

### 6.7 ⚠️ 还没被验证的部分

**以上全部数字都来自自动化机器人。真人验证一次都没做过。**

机器人不会：犹豫、重读、舍不得用道具、因为氛围而放慢、因为挫败而退出。
所以：

| 结论 | 可信度 |
|---|---|
| 两个角色都能通关 | **高**（结构性问题，机器人足以暴露） |
| 死亡分布不再复合爆炸 | **高**（同上） |
| 单局时长落在 30~45 分钟 | **低** —— 实测回合数 42（速通）~ 3074（全清），真人落在中间但无法确定 |
| 难度"好玩" | **未验证** —— 速通中位死亡已降到 0，可能偏简单 |
| 重开率 | **未验证** —— 没有任何观测机制 |

## 七、给第二幕的建议

1. **先玩一遍第一幕再动手。** 这份文档能告诉你结构，但告诉不了你手感。
2. **沿用 flag 收敛的做法。** 不要写选择树。第一幕 10 个节点、3 个结局，
   结局只依赖 5 个 flag —— 这个比例是可以扩展的。
3. **`requiresTag` 的选项每个节点至少留一条非门控的。** 否则没有对应 tag 的角色会卡死，
   有测试守着这条。
4. **新角色的 tag 必须没被占用。** 现有六个：`scholar` `lucid` `frail` `healer` `believer` `steadfast`。
5. **加完内容跑 `pnpm validate`。** 它会检查引用完整性、结局可达性、角色门控、
   以及**平衡守卫**（任一角色中位死亡 ≤ 5、两角色难度差 ≤ 4 倍）。
6. **别只测 `rush` 打法。** 第一幕最大的一个坑就是"速通守卫全绿，探索打法死 100 次"。
   可玩性要看 `normal` 打法的首次死亡深度和能否跑完。
