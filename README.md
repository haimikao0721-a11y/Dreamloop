# 梦境循环 · Dreamloop

> 一层层往下走，每次变强都要拿理智去换。

一个**文字肉鸽**。传统地牢 + 剧情向分支叙事 + 全屏故事段落，
内容全部数据化，为社区扩展而设计。

**当前状态：第一幕 demo（可玩）**

---

## 快速开始

```bash
pnpm install

pnpm dev        # 开发服务器（--host，手机可通过局域网 IP 访问）
pnpm verify     # 类型检查 + 构建 + 全部测试（提交前跑这个）
pnpm test       # 只跑测试
pnpm build      # 生产构建到 dist/
```

**手机上试玩**：`pnpm dev` 之后看终端输出的 Network 地址，手机跟电脑连同一个 WiFi 就能打开。

**分享具体某一局**：地址后面加 `?seed=42&role=ward_nurse`，对方点开直接进同一张地图。

## 它是什么样的游戏

- **传统地牢**：随机生成的房间与走廊，回合制，撞上去就是攻击
- **剧情向**：清空房间会掉出「叙事物件」，捡起来触发全屏剧情段落
- **选择有后果**：选项写入 flag，结局由 flag 组合判定 —— 不是一棵选择树
- **角色即视角**：两个角色的 tag 完全不重叠，同一段剧情看到的选项不同
- **死亡即醒来**：死了不是读档，是"又在梦里醒了一次"。flag 全部保留，
  死得越多你知道得越多。**这是本作最重要的原创点**

### 核心张力

**理智既是命，也是货币。**

读不该读的东西要扣理智，换取力量也要扣理智，低理智时还会持续流失。
变强和保命抢的是同一个资源 —— 单资源双用途，这是肉鸽设计里最优雅的一种张力。

### 官方只做绝望线

第一幕结束时，所有角色都会死。没有好结局。

**好结局留给社区扩展去写。** 官方负责定义"什么是不可能的"（比如"死者不归"），
社区探索的是"死得有没有意义"。这不是偷懒，是为了让社区创作**增强**主题而不是拆台。

## 项目结构

```
src/
├─ core/              纯 TS 逻辑核心，零 DOM 依赖
│  ├─ types.ts          契约层：所有类型定义
│  ├─ engine.ts         状态机：createInitialState + reduce
│  ├─ map.ts            地牢生成（含叙事槽位预留）
│  ├─ narrative.ts      叙事引擎：槽位填充、选项过滤
│  ├─ combat.ts         战斗结算
│  ├─ effects.ts        效果词汇表的唯一实现
│  ├─ conditions.ts     声明式条件求值
│  ├─ endings.ts        结局判定 + "差一点就走到"
│  ├─ content.ts        内容包注册表（支持多包 + mod 覆盖）
│  ├─ rng.ts            确定性随机数（种子复现）
│  └─ index.ts          运行时 API
├─ data/
│  ├─ index.ts          内容包入口，再导出 CORE_PACK
│  └─ packs/core/       第一幕内容：2 角色 / 6 怪 / 10 物品 / 10 剧情 / 3 结局
└─ ui-web/            响应式 UI + 四种输入适配器

assets/
├─ characters/        角色动作，按角色 id
├─ map/               地形
├─ items/             物品
└─ cutscenes/         过场画面

docs/                 设计文档与内容作者手册
tests/                引擎、内容、界面与构建产物
```

## 五条工程纪律

这些不是风格偏好，是架构地基。破坏了任何一条，前面列的收益都会消失。

1. **`core` 里禁止出现 `window` / `document` / DOM / CSS**
   所有表现通过 `GameEvent` 往外交。
   → 保证 core 能在 node 里跑测试，也能复用到 TUI / 桌面壳 / 服务端。

2. **禁止 `Math.random()`**
   随机性只能来自 `state.rngState`。
   → 同一个 seed 必然复现同一局；bug 可定位；玩家可分享"神种"。

3. **`reduce(state, intent)` 是纯函数**
   同样的输入必然得到同样的输出，不读全局变量。
   → 存档 = 序列化 state；回放 = 录 Intent 流。

4. **所有输入源只产出 `Intent`**
   虚拟方向键 / 点格子 / 滑动 / 键盘 / 手柄 → `Intent` → core。
   core 收到 Intent 时**不知道**玩家用的是手机还是键盘。

5. **内容里禁止出现代码，代码里禁止出现具体内容**
   加 100 个怪不改一行引擎代码。

这五条带来的直接好处：**打包成 exe / apk 时，游戏逻辑零改动。**

## 测试在守什么

```bash
pnpm test
pnpm verify    # 类型检查 + 构建 + 全部测试
```

| 测试文件 | 守什么 |
|---|---|
| `engine.test.ts` | 种子复现、纯函数性、伤害公式边界、条件求值、2000 步模糊测试 |
| `content.test.ts` | 内容引用完整性、角色门控、结局可达性、**平衡守卫**、节奏测量 |
| `ui-smoke.test.ts` | UI 能挂载、所有 GameEvent 都有处理、四种输入、分享降级 |
| `dist-smoke.test.ts` | **构建产物能跑起来**、相对路径可子目录部署 |

写内容的人只需要跑内容那部分：

```bash
pnpm validate   # = vitest run tests/content.test.ts
```

几条值得单独说的：

- **平衡守卫**：两个角色的中位死亡次数不得差 4 倍以上。
  曾经记梦者是 17 次、护士 2 次（6 倍）—— 那不是"两种玩法"，是"一个不能玩"。
- **内容引用完整性**：内容引用错一个 id，引擎不会崩（所有查找都兜住了），
  但那段内容会**静默失效**。这是社区提交内容时最容易犯又最难发现的错。
- **构建产物冒烟**：单元测试跑源码，玩家拿到的是打包后的字节。两者隔着压缩和
  tree-shaking，所以直接把 `dist/app.js` import 进来真的启动一遍。

## 授权

**代码与内容分开授权** —— 因为「让别人用你的引擎」和「让别人拿你的世界观去卖」
是两件事。

| 部分 | 协议 | 文件 |
|---|---|---|
| **代码**（`src/core/`、`src/ui-web/`、`tests/`） | **MIT** | [LICENSE](LICENSE) |
| **内容与素材**（`src/data/`、`docs/`、`assets/`） | **CC BY-NC-SA 4.0** | [LICENSE-CONTENT](LICENSE-CONTENT) |

### 这意味着

- **任何形式的非商业二次创作都欢迎** —— 改剧情、加内容、做 mod、写同人，随便
- 代码可以自由使用，**包括商业使用**
- **内容与素材不得用于商业目的**（想做请先联系我们）
- **贡献者保留自己内容的版权** —— 你写的东西是你的
- 基于本内容的二创必须**保持同样的开放协议**（SA 条款）

### 相关文件

- [CLA.md](CLA.md) —— 贡献者许可协议（提交 PR 前请读一遍）
- [REVENUE.md](REVENUE.md) —— 收益分配政策

### 需要知道的

**这不再是严格意义的「开源软件」。** 限制商业使用不符合 OSI 的
《开源定义》第 6 条，准确的叫法是 **source-available**（源码可见）。

我们选择这样做是因为：**代码不是这个项目的护城河，内容和世界观才是。**
代码用 MIT 换取最多的贡献者；内容用 NC 卡住「拿这个世界观去赚钱」这件事。

如果你对这套安排有想法，欢迎开 issue 讨论。
